# 📊 Visuals

The held library for finished visuals. The Design team, dispatched by the `visualize` skill, files its standalone visuals here: charts, diagrams, dashboards, interactive widgets, and explanatory illustration. Visuals are deliverables, rendered by the team and kept here for reference, the visual counterpart to the Reports library (`Inbox/Reports/`).

## Held, not sorted

Visuals live here and stay here. They are not sorted into the BRAIN's permanent layers: a saved visual is a rendered artifact, produced, held, used, and eventually cleared or superseded, not durable reference knowledge. The session-start Inbox sweep skips this folder the way it skips the Reports library and the team homes, so a visual is never proposed for re-sorting. Visuals stay fully linted and cataloged like any other vault file.

## Archival, kept until superseded

A saved visual is a snapshot, not an expiring report, so this library carries no blanket freshness window. A chart records the data it was built from at a point in time; a diagram holds until the structure it shows changes. Each visual carries the date of its underlying data in its index entry below (its provenance) and the question it answers. When the data changes, the visual is regenerated rather than re-verified, and the stale one is cleared or replaced. A visual is removed only when it is superseded or no longer needed.

## What is filed here, and what is not

This library is the default home for a standalone visual: one that answers a question on its own and does not belong to a specific Project, Venture, or note. A visual that belongs with its context (a chart inside a project's analysis, a diagram in a Library article) is saved into that home instead, not here. Most visuals render inline in chat and are never saved at all; only a visual the Founder asks to keep is filed, here or in its named home.

## This file is the visuals index

`Visuals.md` is the one hub that links every held visual. The index below carries a wikilink to each visual artifact (an `.svg` or self-contained `.html` file) in this folder, with the question it answers and its data date, so the whole library is browsable from here and in the graph view. This index is the only place a visual is linked: no other file in the BRAIN cites or links to a held visual, which keeps the wider wikilink graph free of disposable nodes. A visual can also be found by searching this folder. Because a rendered `.svg` or `.html` artifact carries no BRAIN frontmatter, its provenance (the question, the data date, the source) lives in its index entry here.

The index is kept in lockstep with the folder. When a visual is filed, regenerated, or cleared, its entry below is added, updated, or removed in the same edit, so the index always mirrors what is actually here.
