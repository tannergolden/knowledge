# 📊 VISUALS

<a name="top"></a>

**The held library of finished visuals, each dated by the data behind it.**

_A snapshot of its data, regenerated rather than re-verified._

---

## 💡 What This Folder Is For

The held library for finished visuals. Standalone visuals land here, by the rules below: charts, diagrams, dashboards, interactive widgets, and explanatory illustration. Visuals are deliverables, rendered and kept here for reference, the visual counterpart to the Research library (`Inbox/Research/`).

---

## 📌 Held, not sorted

Visuals live here and stay here. They are not sorted into the BRAIN's permanent layers: a saved visual is a rendered artifact, produced, held, used, and eventually cleared or superseded, not durable reference knowledge. The session-start sort skips this folder, as it skips the Research library and the idea pool (`Inbox/README.md`), so a visual is never proposed for re-sorting.

---

## 🗄️ Archival, kept until superseded

A saved visual is a snapshot, not an expiring report, so this library carries no blanket freshness window. A chart records the data it was built from at a point in time; a diagram holds until the structure it shows changes. Each visual carries the date of its underlying data in its index entry below (its provenance) and the question it answers. When the data changes, the visual is regenerated rather than re-verified, and the stale one is cleared or replaced. A visual is removed only when it is superseded or no longer needed.

---

## ⚖️ What is filed here, and what goes elsewhere

This library is the default home for a standalone visual: one that answers a question on its own and does not belong to a specific project, venture, or note. A visual that belongs with its context (a chart inside a project's analysis, a diagram in a Library article) is saved into that home instead, not here. Most visuals render inline and are never saved at all; only a visual the owner asks to keep is filed, here or in its named home.

---

## 🧾 Filing a visual

A saved visual is an `.svg` or self-contained `.html` file, named for what it shows. It is not a note: it carries no BRAIN frontmatter, so the linter and the catalog pass it by, and its provenance (the question it answers, the date of its data, its source) lives in its index entry, added in the same edit (below).

---

## 🔗 This README is the visuals index

This README is the one hub that links every held visual. The index below carries a wikilink to each visual in this folder, with the question it answers and its data date, so the whole library is browsable from here. This index is the only place a visual is linked: no other file in the BRAIN cites or links to a held visual, which keeps the wider wikilink graph free of disposable nodes. A visual can also be found by searching this folder.

The index is kept in lockstep with the folder. When a visual is filed, regenerated, or cleared, its entry below is added, updated, or removed in the same edit, so the index always mirrors what is actually here.
