# ⚙️ System/

## Rules

- Change a `System/` file only when your user directs it: each one is a deliberate setting. Files here override an agent's defaults, and yield to `AGENTS.md` and each folder's Rules (Priority Order, below). With no `System/` file for a setting, follow `AGENTS.md` and `Profile/Working Style.md`.
- `System/Data/` is generated by `update-vault.py`. Never edit it by hand or read it for how to behave; read `catalog.ndjson` to see what notes exist without walking the tree.
- A vault script lives in `.github/scripts/`, finds the vault from its own location (`__file__`, two folders up) and never holds an absolute path: an index or manifest it stores uses paths from the vault root. Writing Scripts, below, says the rest.
- A report on working on the vault itself ends with a copy-paste prompt that fixes what it found (Reports On The Vault, below).

## Purpose

`System/` is the AI configuration layer of this BRAIN. It contains files that define how the AI should behave, what workflows it should follow, what persona it should adopt, and what operating context applies to this specific user's environment. Files here take precedence over general AI defaults where they overlap.

Think of this folder as the control panel: `AGENTS.md` is the rulebook, and `System/` holds the specific dials and settings.

## Folder Structure

`System/` is a flat **operating surface** at the root (the docs you read), the `Skills/` library of installable capabilities, and the generated `Data/` folder. The vault's scripts are not here: they live in `.github/scripts/`, beside the CI that runs them, so `System/` holds only what the vault reads.

### Operating surface (`System/` root)

| Path | Purpose |
|------|---------|
| `System.md` | This file. |
| [[System/Workflows\|Workflows.md]] | Strategy and capture loops the AI follows. |
| `Persona.md` · `Context.md` · `Integrations.md` | Optional config files *(create as needed)*. |

### `Skills/` - installable capabilities

| Path | Purpose |
|------|---------|
| [[System/Skills/Skills\|Skills/Skills.md]] | Packaged `.skill` artifacts at the root; skill sources hidden in `.unpackaged/` (external format, no wikilinks, not walked as notes). A skill composes a team from the federated agent library and carries no agents of its own; its archive carries the team, vendored when it is built. |

### `Data/` - generated files

Machine-written and never hand-edited; `.github/scripts/update-vault.py` draws both, and CI fails when either is out of date. Group overview: [[System/Data/Data|Data/Data.md]].

| Path | Purpose |
|------|---------|
| `Data/catalog.ndjson` | One JSON record per note (`.template/` scaffolds excluded): path, title, type, keywords, description and status. The vault's live listing of what exists, readable by any AI or tool. |
| `Data/agent-catalog.json` | Every agent (spoken name, role, home, team, description) and every team roster in the federated agent library. The agents themselves are the source of truth; skills check a name against this before dispatching it. |

## Tooling

The vault's checks and generators are scripts in `.github/scripts/`, run from the vault root as `python3 .github/scripts/<script>`. Each one finds the vault from its own location (Rules, above), needs only Python 3's standard library, and exits non-zero on a finding. `.github/workflows/vault.yml` runs every check, through the action in `.github/actions/vault/`, on each pull request and each push to the default branch.

| Script | What it does |
|--------|--------------|
| `check-vault.py` | Runs every check below, as CI does. The one command to run before a commit. |
| `lint-notes.py` | Every note's frontmatter and naming against the schema (`.docs/technical/vault/Note-Schema.md`) and its keywords (`.docs/technical/vault/Keywords.md`). |
| `check-links.py` | The wikilink graph: every link resolves and follows the hub topology (`.docs/technical/vault/Link-Topology.md`). |
| `check-skills.py` | Each skill source against the Agent Skills format and the layout in `Skills/Skills.md`. |
| `check-agents.py` | Each agent spec and team roster, and one namespace across every home. |
| `scan-pii.py` | Social Security and card numbers in tracked files. Keys and tokens are the gitleaks scan's job in `checks.yml`. |
| `update-vault.py` | Draws everything generated: the memory cascade, every `brain:` block, both catalogs, the skill archives and the `.gitkeep` markers. `--check` writes nothing and fails when anything is stale. |
| `session.py` | The session helpers, run by hand: the session-start card, the check after a note is written, and the end-of-turn redraw. |
| `profile-coverage.py` | How filled in each Profile facet is; the identify skill reads its `--json`. |
| `knowledge-base.py` | Offline reference works (Wikipedia and more) in `Library/Reference & Encyclopedia/`: `list`, `enable`, `refresh`, `search`, `read`. Every source ships off. |

Each script is tested by the `test_*.py` file beside it, and `.github/scripts/README.md` lists them all. The writes the retired engine once made for the AI, such as a memory entry, a session summary or a new note, the AI now makes with its own tools, in the format each folder's note documents (`AGENTS.md`, Start here).

## Reports On The Vault

Any report about working on the vault itself (its structure, rules, checks or tooling), as distinct from a report made by using the vault, ends with one copy-paste prompt in a fenced code block. Pasted into a fresh session, it has the agent fix what the report found, highest priority first.

Scope the prompt to concrete, bounded fixes the next session can make directly: a test to add, a command to run, a file to correct. Leave out open-ended authoring, such as filling in Profile or writing Memory entries: that belongs in the report's body as a recommendation. Lead with the most important fix, name the report and the fixes chosen, and restate the standing safeguards: commit before editing, and run `check-vault.py` when done.

Separate the prompt's sections (the opening line, each numbered fix and the closing rules) with a line holding one zero-width space (U+200B) and nothing else, exactly one between sections. A chat composer collapses empty lines on paste; that line survives, so the sections stay apart.

## Writing Scripts

A new vault script goes in `.github/scripts/`, beside the others, and follows them:

- One job per script, named verb-noun with hyphens (`check-links.py`); its tests go in `test_<name>.py` beside it, which CI discovers on its own.
- Standard library only, and runnable on Python 3.9 (`from __future__ import annotations`), because they run on whatever `python3` the machine has.
- The module docstring's first line is the script's purpose, since the folder's File Log reads it; the rest says why it exists and how to run it.
- Self-locating: import `vault.py` from the script's own folder, take the vault root from `--root` (the repository by default), and never hardcode a path (Rules, above).
- Exit 0 when clean, 1 on findings, 2 on misuse, and print one finding per line; `vault.Report` does both, with GitHub annotations under Actions.
- Generated output is deterministic (sorted, no timestamps), so CI can tell a stale file from a fresh one.

## Priority Order

When `System/` files conflict with other parts of the BRAIN:
1. `AGENTS.md`: the Constitution's Invariants, then the vault's rules. Always wins.
2. The Rules in each folder's note, which add to `AGENTS.md` and never loosen it.
3. `System/` files, which win over Profile and an agent's own defaults on behavioral settings.
4. `Profile/Working Style.md`, where no `System/` file says otherwise.

## What Belongs Here vs. Elsewhere

| Content Type | Belongs In |
|-------------|-----------|
| How this AI should communicate with this user | `System/Persona.md` *(create as needed)* |
| The user's natural communication preferences | `Profile/Working Style.md` |
| Governance rules for AI behavior | `AGENTS.md` |
| A folder's rules and procedures | That folder's note |
| Project-specific workflows | `Projects/[project]/` |
