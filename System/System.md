# System/

## Purpose

`System/` is the AI configuration layer of this BRAIN. It contains files that define how the AI should behave, what workflows it should follow, what persona it should adopt, and what operating context applies to this specific user's environment. Files here take precedence over general AI defaults where they overlap.

Think of this folder as the control panel - if `Instructions.md` is the operating manual and `Constitution.md` is the rulebook, `System/` is where the specific dials and settings live.

---

## Folder Structure

`System/` is organized as a flat **operating surface** at the root (the docs you read, the tools you run, and the `changelog.md`), the `Skills/` library of installable capabilities, the engine's generated `Data/` folder, and the hidden `.backups/` (with an ad-hoc `Backups/` alongside). Two root files have Constitution-fixed paths and cannot move: `brain.command` (Articles 3.5 / 7.8) and `changelog.md` (Article 3.6).

## Scripts

All scripts in the BRAIN share a single error log: `System/Data/errors.log`. This is a non-negotiable convention - every script, present and future, must write errors there using the same format:

```
[YYYY-MM-DD HH:MM:SS] [script-name] [ERROR] message
```

Alongside it, `brain.command` keeps an **activity log** at `System/Data/reports.log`: one line per state-changing command, the success-side companion to the error log. The write is centralized in `_finish_ledger` and gated by `_is_mutating`, so read-only commands and read-only subcommands (`sync verify`, `backup list`, `memory status`, `gitkeep check`, `git status`) never appear there. It auto-trims to the most recent 1000 lines.

This ensures errors from any source are visible in one place and can be reviewed together. `brain.command` reads this file for the `health` command; any script that bypasses it breaks that visibility.

`System/brain.command` is the unified Python CLI for all BRAIN maintenance tasks. It self-locates using its own file path - no hardcoded paths, works wherever the BRAIN is placed. Generated data files (manifest, snapshot) live in `System/Data/`.

### `brain.command`

**Primary usage:** The AI runs `brain.command` directly via bash - no user interaction needed for routine tasks like `sync`, `manifest`, `lint`, and `health`. Resolve the BRAIN root at runtime and invoke:

```bash
python3 "/path/to/BRAIN/System/brain.command" <command>
```

The script can also be run interactively - double-clicking in Finder opens a Terminal window with a paged, importance-ordered menu (5 commands per page):

- **Page 1 - Session Core:** Session Startup, Health Check, Context Load, Surgical Read, Backup File.
- **Page 2 - Capture & Create:** Log Memory, Session Summary, Inbox Status, New Project / Venture, Tiered Memory.
- **Page 3 - Memory & Graph:** Consolidation Worksheet, Wikilink Graph, Rename, Sync Finder Tags, Rebuild Index.
- **Page 4 - Index & History:** Change Diff, Changelog Entry, Git Snapshot, Skill Packager, Frontmatter Lint.
- **Page 5 - Diagnostics & Extras:** Stale Scan, Gitkeep Maintenance, Two-Stage Trash, Registry Verify, Token Estimates.
- **Folder bundles:** from any page the accelerator keys `i` / `r` / `v` / `p` / `l` print the Profile, Memory-Recall, Ventures, Projects, or Library bundle directly.

Search lives on the accelerator key `s` from any page rather than a numbered slot - it is reached constantly and never deserves a page flip. Type `1`–`5` to run a command on the current page, `s` for Search, `n` to page forward (next), `b` to page back, `h` for the command guide, `i`/`r`/`v`/`p`/`k` for folder bundles, a command's name from any page, or `q` to quit.

### Terminal Usage

Navigate to the BRAIN folder, then:

```
python3 System/brain.command                    # interactive menu
python3 System/brain.command <command>          # run directly
python3 System/brain.command search "query"     # commands that take arguments
python3 System/brain.command load "task desc"
python3 System/brain.command new project "Site" --yes
python3 System/brain.command load "task" --json
```

## AI Instructions - Writing Scripts

These standards apply to every script the AI creates or modifies in the BRAIN, regardless of language (Python, bash, or otherwise):

**Error handling:**
- Every script must handle errors explicitly - no silent failures
- Wrap file operations, subprocess calls, and external dependencies in try/except (Python) or conditional checks (bash)
- All errors route to the shared log `System/Data/errors.log`, one line per error carrying four fields: timestamp, script (and component), level, message - the same shape `brain.command` writes: `YYYY-MM-DD HH:MM:SS  [script-name / component]  ERROR  message`
- Never let a logging failure crash the main script - wrap log writes in their own error handler
- On fatal errors, print a clear message and exit with a non-zero code

**Canonical boilerplate - paste this into every new script.** It self-locates the BRAIN root (Constitution 2.5), attaches the shared log, and degrades to a null handler if the log can't be opened, so logging can never crash the script.

Python:

```python
import logging, sys
from pathlib import Path

BRAIN = Path(__file__).resolve().parent
while not (BRAIN / "Constitution.md").is_file():      # self-locate the BRAIN root
    if BRAIN.parent == BRAIN:
        sys.exit("❌ BRAIN root not found")
    BRAIN = BRAIN.parent
try:
    _h = logging.FileHandler(BRAIN / "System/Data/errors.log", encoding="utf-8")
except OSError:
    _h = logging.NullHandler()                        # log failure never crashes the script
logging.basicConfig(level=logging.ERROR, handlers=[_h],
    format="%(asctime)s  [SCRIPT-NAME / %(name)s]  %(levelname)s  %(message)s",
    datefmt="%Y-%m-%d %H:%M:%S")
log = logging.getLogger("main")

# usage at any failure point:
#   except OSError as e:
#       log.error(e, exc_info=True)
#       print(f"❌  {e}"); sys.exit(1)
```

Bash:

```bash
BRAIN="$(cd "$(dirname "$0")" && pwd)"
while [ ! -f "$BRAIN/Constitution.md" ]; do
  BRAIN="$(dirname "$BRAIN")"
  [ "$BRAIN" = "/" ] && { echo "❌ BRAIN root not found"; exit 1; }
done
log_error() {  # log_error "message"  - never fails even if the log is unwritable
  printf '%s  [SCRIPT-NAME]  ERROR  %s\n' "$(date '+%Y-%m-%d %H:%M:%S')" "$1" \
    >> "$BRAIN/System/Data/errors.log" 2>/dev/null || true
}
```

Replace `SCRIPT-NAME` with the script's filename. Errors logged this way surface automatically in `health` (its error-log review step reads the shared log), so a script that fails quietly in one session is caught in the next.

**Emojis:**
- Use emojis in terminal output to make status scannable at a glance
- Standard conventions used across BRAIN scripts:
  - ✅ - success / completed
  - ❌ - error / failure
  - ⚠️ - warning / non-fatal issue
  - ⏳ - in progress / waiting
  - 📂 - folder / path reference
  - 📄 - file reference
  - 💾 - save / backup operation
  - ⛔ - hard stop / abort
- Do not use emojis inside `errors.log` entries - the log is plain text for programmatic parsing

**Structure:**
- Scripts must be self-locating - resolve all paths at runtime from `__file__` or `$0`, never hardcode
- Include a comment block at the top describing what the script does
- Log the script name in every `errors.log` entry so the source is always identifiable

## Priority Order

When `System/` files conflict with other parts of the BRAIN:
1. `Constitution.md` - always wins
2. `Instructions.md` - wins over System files on structural matters
3. `System/` files - win over Profile and general defaults on behavioral configuration
